# Drive Snapshots

**Read-only disk snapshots. Offline exploration. A clearer picture of what changed.**

[English](README.md) · [简体中文](README.zh-CN.md) · [Demo](demo/index.html) · [Contributing](CONTRIBUTING.md) · [Agent guide](AGENTS.md)

Capture folder sizes with PowerShell, compare snapshots in a browser, and keep your filesystem inventory on your own machine. No accounts, cloud service, build toolchain, or runtime packages.

- **Configure once:** multiple drives or directories, output location, reporting depth.
- **Explore locally:** searchable directory tree and clickable area-proportional treemap.
- **Follow changes:** pick a baseline, switch snapshots, or play history.
- **Share deliberately:** export a standalone HTML with embedded data, CSS, and JavaScript.
- **Work with agents:** focused skills for snapshot capture, growth analysis, cleanup planning, and report creation.

## Try the demo

It is a standalone file with four fictional snapshots: growing projects, new folders, and disappearing downloads. All demo data is generated by [scripts/build-demo.ps1](scripts/build-demo.ps1); none comes from a real disk. GitHub displays HTML source; download it to view, or serve only `demo/` with GitHub Pages.

## Quick start

Requires **PowerShell 7.2+** (`pwsh`). Windows is the primary local test platform; CI runs the smoke tests on Windows, Linux, and macOS. Windows PowerShell 5.1 is not supported. The viewer needs only a modern browser.

```powershell
# 1. Choose roots, output location and detail budget; assess and save per-root depths.
./initialize-snapshots.ps1

# 2. Capture a snapshot with your saved settings.
./drive-snapshot.ps1

# 3. Repeat later, then generate a standalone report.
$files = (Get-ChildItem ./snapshots -Recurse -Filter *.csv).FullName
./export-report.ps1 -Snapshot $files -Output ./reports/latest.html
# Open reports/latest.html in your browser.
```

Alternatively, open `viewer/index.html` and use **Import CSV snapshots**. Select multiple files in one import to load history. Imports replace the current dataset. Exported reports and the demo can save a new standalone report directly from the browser; the unbundled viewer's export requires HTTP because browsers restrict `file://` asset fetching. The PowerShell exporter always works offline.

### Configuration

Initialization writes the Git-ignored `snapshot.config.json`; see [the example](snapshot.config.example.json). It will not overwrite an existing config. Edit the file to change saved settings.

```powershell
# Non-interactive setup (choose your own paths).
./initialize-snapshots.ps1 -Path 'C:\Users\Public','D:\Projects' -OutDirRoot 'D:\Snapshots' -MaxDepth 4

# One-off scan; command-line settings override the config.
./drive-snapshot.ps1 -Path 'D:\Projects' -MaxDepth 3

# Alternate configuration location.
./drive-snapshot.ps1 -Config ./snapshot.local.json
```

| Setting | Meaning |
| --- | --- |
| `paths` / `-Path` | One or more directory or drive roots; no machine-specific default. |
| `outputDirectory` / `-OutDirRoot` | Defaults to `snapshots` beside the configuration file. |
| `maxDepth` / `-MaxDepth` | Fallback reported depth, default 5; explicit CLI value overrides all per-root defaults. 0 means root only. |
| `maxDepthByPath` | Per-root depths generated by initialization; takes precedence over the fallback. |
| `-Config` | Configuration file; relative scan and output paths resolve beside this file. |

The scanner always traverses the full subtree to obtain recursive totals. Depth limits **reported rows**, not scanning cost. Separate root folders use a readable label plus a path hash; timestamped filenames retain history. The configured output directory is excluded from scanning. Use the same output directory and scope for comparable runs.

## Read the results correctly

Each UTF-8 log contains an aligned scan summary, UTC timestamps and duration, volume capacity, the 30 largest immediate subfolders, and numbered read failures. Sizes use GiB and exact bytes. Volume allocation is separate from observed logical size. `PARTIAL` means a lower bound; `OK` means no recorded read errors, not guaranteed atomic coverage. Full paths are retained without table truncation. Historical logs are not rewritten.

CSV columns remain compatible with the original scanner:

| Column | Meaning |
| --- | --- |
| `Depth`, `Path` | Root is depth 0; absolute folder path. |
| `SizeBytes`, `SizeGiB` | Recursive logical file size; GiB = 2³⁰ bytes. |
| `FileCount` | Recursive count of observed regular files. |
| `DirCount` | Immediate child directory count, including skipped directory links. |
| `Reparse` | Directory link/junction skipped to avoid loops. |
| `Unreadable` | This directory encountered a read failure. |
| `Incomplete` | Read failure here or in a descendant (new column). |

Scans run without automatic elevation and modify no scanned files. They write only output CSV/logs (and configuration when initializing). Directory links are reported but not followed; file links are skipped. The root itself cannot be a link. Hard links can be counted more than once, and compression/sparse files are not measured as allocated space. A scan is not an atomic filesystem snapshot: files may change during traversal.

Permission failures produce **lower bounds**, not zero-sized proof. Legacy CSV files lack propagated `Incomplete` information. Comparisons require matching root and maximum observed depth; legacy CSV does not record all scan settings, so identical filters/permissions remain your responsibility. A missing path means **not observed**, not proven deletion. Renames appear as disappearance plus appearance. Do not add recursive parent and child sizes together.

The treemap shows immediate children plus direct files/unreported detail. Changes list up to 50 immediate child folders; direct-file changes are reflected in total size. History sorts by filename (use timestamped names), initially selecting the latest filename. It does not watch the filesystem: scan again and re-import or regenerate the report. The folder list shows up to 1,500 matching rows; search narrows it. Scanning keeps one record per directory in memory, and large reports may be slow in browsers.

## Privacy and publishing

`.gitignore` excludes local CSV/log files, `snapshots/`, `reports/`, local configuration, generated HTML, and legacy single-letter drive folders. Only the synthetic demo CSV/HTML is allowlisted. For custom config/report names and JSON exports, add corresponding ignore rules before staging. Ignore rules do not remove already tracked files.

Reports embed full paths and sizes. Share a report only when you intend to share that inventory. For a public demo, publish **only `demo/`**. Do not serve your snapshot directory publicly.

```powershell
git status --short
git ls-files                    # Review the complete publishable inventory.
git check-ignore snapshots/example.csv snapshot.config.json reports/latest.html
```

## Protected system folders

Windows users can explicitly request UAC elevation:

```powershell
./drive-snapshot.ps1 -Path 'C:\' -Elevate
```

Elevation is optional and never requested automatically. Cancellation or child-process failure is an error, not a successful scan. Administrator access can improve coverage but cannot read every SYSTEM-protected, locked, or changing resource. Other operating systems can run `pwsh` with appropriate privileges; `-Elevate` itself is Windows-only.

When any read fails, the scanner emits a warning, records failed paths in the log, sets `Unreadable` on the affected directory, and propagates `Incomplete` to all ancestors, even when failures occur below the reported depth. The viewer labels partial coverage and warns that differences may reflect permissions. For system-disk comparisons, use consistent privilege levels and inspect both logs before interpreting growth. It never substitutes a guessed size for inaccessible data.

## Recommend a reporting depth

```powershell
# Windows: assess every ready fixed disk for the current user.
$assessment = ./measure-snapshot-depth.ps1
$assessment | Format-Table Path,RecommendedMaxDepth,RecommendedRows,RecommendationBasis,Confidence
# Inspect each depth increment, including incomplete levels.
$assessment | ForEach-Object { $_.Path; $_.DepthRows | Format-Table }

# Explicit roots, also supported on Linux/macOS.
./measure-snapshot-depth.ps1 -Path 'D:\Projects' -TargetRows 50000
# Previous policy: deepest complete level within the row budget.
./measure-snapshot-depth.ps1 -Path 'D:\Projects' -Strategy Budget
```

The default `Growth` strategy examines the cumulative directory count at every depth. `AddedRows` shows the increase from the previous level, and `GrowthRatio` is the current cumulative count divided by the previous count. The first complete level adding at least **5,000 directories** and multiplying cumulative rows by at least **3** is recommended. This includes the first substantial expansion so its detail remains visible; it does not stop one level before it. Both thresholds are configurable (`-MinAddedRows`, `-GrowthFactor`). These are transparent heuristics, not a proven optimal depth or a cleanup-value estimate. No drive-letter rules are used.

If no qualifying expansion is observed, the fallback is the deepest complete level within `TargetRows`. `-Strategy Budget` always uses that fallback. Default per-root probe ceilings are **50,000 rows**, depth 12, 500,000 inspected entries, and 20 seconds. A 1,500-row ceiling is compact; 200,000 allows more exploration. The ceiling bounds probing, not the size of the final recommendation. A truncated level cannot establish a growth point, and a larger ceiling can reveal previously hidden growth. Files consume the entry budget but only directories contribute report rows. Budgets are checked between filesystem operations; one blocked operation can exceed the time budget.

`DepthRows` includes depth, added rows, cumulative rows, growth ratio, enumeration completion, and growth markers. Counts on incomplete levels are lower bounds. `RecommendedRows` is the count at the chosen depth; `ObservedRows` can include part of a deeper level. `RecommendationBasis` explains the choice; `StopReason` separately explains why probing ended. `LevelComplete` means enumeration reached the end of that level, not that every directory was readable. Permission failures or time/entry truncation produce `Low` confidence; an inaccessible root produces no recommendation (`Unavailable`). Even `Observed` describes visible directories only. No file contents are read and links are not followed.

Windows automatic discovery includes ready fixed disks only; pass other roots explicitly. On other platforms `-Path` is required. Run from an administrator PowerShell for a privileged assessment; no automatic elevation or ACL changes occur. Keep privileges and exclusions consistent with the intended scan.

Results are saved to the Git-ignored `reports/depth-assessment.json`; `-Output ''` disables writing. The default exclusions are the script's `snapshots/` and `reports/`; use `-ExcludePath` for custom locations. Assessment alone never rewrites configuration. MaxDepth still limits reported detail, not the scanner's full traversal cost.

### First-run initialization for users and agents

`./initialize-snapshots.ps1` is the shared first-run entry. It asks for roots, output location, and probe row ceiling, prints the depth-by-depth table, and saves the selected depths plus assessment evidence in private configuration. Run `./drive-snapshot.ps1` afterwards to capture file sizes. The compatibility entry `./drive-snapshot.ps1 -Init` delegates to the same initializer.

```powershell
# Non-interactive first setup; the default growth policy is applied independently per root.
./initialize-snapshots.ps1 -Path 'C:\','D:\' -OutDirRoot 'snapshots'
./drive-snapshot.ps1
```

Initialization accepts the same strategy, growth thresholds and probe limits. `-MaxDepth` explicitly chooses one depth for all selected roots while retaining assessment evidence. Precedence during scanning is explicit `-MaxDepth` → matching `maxDepthByPath` → global `maxDepth`. Existing version-1 configurations remain valid. Existing files are never overwritten; edit them or select another `-Config`.

Partial assessments save tentative recommendations with a warning. An unreadable root needs restored access or an explicit depth before saving. For privileged setup, run from an administrator PowerShell or use `./drive-snapshot.ps1 -Init -Elevate`. Agents use the snapshot-capture skill and this same entry with already-known arguments, asking only for missing scope/preferences. Run `./tests/depth.ps1` for recommendation, initialization and per-root-default tests.
